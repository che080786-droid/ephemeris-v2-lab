# 明月 × 晏景｜我们的家：UI 改造方案

本文记录已讨论的 UI 方案，供后续确认与施工使用。保存本文不代表开始实施。

建议把“明月 × 晏景｜我们的家”设计成一个**以日常、陪伴和共同活动为中心的生活空间**。现有 InternalBeyond-Mobile 继续提供功能，新界面负责重新组织入口与表达方式。

五个一级页面采用 **Home / Learning / Together / Chat / Me**。Memory 银河、英语小屋、角色人设和世界书分阶段接入，本方案不要求迁移数据或改动底层。旧月序未来仅计划保留 Memory 银河 / 生活痕迹的表达方式与英语小屋，其他旧模块暂不迁移，世界书暂不导入。

## 1. 统一视觉语言

Home、Together、Listen Together 三张视觉参考与 Chat 文字描述可以归入同一套视觉语言：**月色、纸张、微光、留白**。参考素材用于理解氛围与层级，不原样复制设计、人物、照片或内容。

| 元素 | 统一规则 |
|---|---|
| 背景 | Day 用暖白与极浅粉灰；Night 用炭灰与带暖意的深色。照片作为可选氛围层 |
| 标题 | 英文衬线用于页面标题与活动名称；中文采用清晰、轻盈的正文排版 |
| 文案 | 具体、简短，表达“回来、坐一会儿、一起听”，避免功能宣传语 |
| 卡片 | 半透明、细边框、轻圆角；仅用于需要聚合或点击的内容 |
| 留白 | 用间距区分层级，减少边框、徽章和嵌套卡片 |
| 强调色 | 暖金用于灯与生活状态；低饱和玫粉用于聊天和少量选中状态 |
| 图标 | 细线、形状清晰；不能只靠浅色区分选中状态 |
| 动效 | 短暂淡入与柔和过渡，尊重现有“减少动效”设置 |

页面之间共享字体、颜色、圆角、间距和导航，但密度可以不同：Home 有生活内容，Together 有活动入口，Chat 以消息为主，Me 更紧凑。

背景摄影不必覆盖每页。Chat 和学习阅读区优先使用安静的纯色，保证长时间阅读舒适。不仿制系统状态栏或动态岛，不以低对比文字、大面积实时模糊或装饰性状态控件牺牲可读性与性能。

## 2. Home：我们的日常

首页以“回到家”为主线，建议按以下顺序组织：

- **时间与问候**：日期、适度放大的时钟、一句欢迎语。
- **我们**：明月与晏景的头像、名字，以及可选的相伴日期。
- **今天的一句话**：直接放在页面上，避免额外套卡片。
- **日常小区域**：便笺、近期日程、来信，按实际内容显示。
- **一起做点什么**：继续听歌、继续共读等真实可用的入口。
- **生活痕迹**：未来再接 Memory 银河；第一阶段不造假数据或空按钮。

相伴天数只有在用户设定起始日期后显示。“今天的一句话”需明确来源，不能让固定欢迎文案看起来像晏景刚刚主动发来的消息。

原有 Calendar、Letters、音乐挂件可以支持首页内容。参考图里的相册目前没有对应的完整模块，不作为第一阶段必做项。信件数量与状态需对应真实数据，不作为装饰数字。

“明月 × 晏景”首先是界面身份，不直接改写已有个人资料、API 配置或角色提示词；这些资料会参与 AI 上下文，不能当作纯装饰文案处理。

## 3. Learning：一起慢慢学

Learning 是学习活动的入口，未来承接英语小屋，当前可先围绕已有 Coread 与 Blog 组织。

| 区域 | 内容来源与定位 |
|---|---|
| 继续阅读 | 复用 Coread 的阅读记录与进度 |
| 阅读材料 | 复用 Blog 材料与分类能力 |
| 英语小屋 | 后续独立 App，承担练习、复习和学习进度 |
| 学习计划 | 后续按需要连接 Calendar |

视觉采用书页感：浅背景、衬线小标题、清晰正文、少量细线。避免一开始堆满打卡、分数、连续天数与统计图。

**Learning 和 Together 的共读入口进入同一套 Coread**：前者强调学习与材料，后者强调陪伴，不重复建立阅读数据。

英语小屋推荐参考观影室，通过 `IBApps` SDK 做成独立 App，再按实际接口能力复用聊天与 Blog 材料。具体能力需要先核对 SDK，不假定其已提供完整学习接口。

## 4. Together：一起做事

最接近 Together 参考图，采用大标题、短中文说明和三个主要入口：

| 入口 | 中文表达 | 复用能力 |
|---|---|---|
| Listen Together | 一起听 | Music / 一起听 |
| Read Together | 一起读 | Coread |
| Watch Together | 一起看 | Cinema |

三张入口卡片可带简短状态，例如“继续上次的阅读”，但只有真实记录存在时才显示。

Cinema 当前通过应用商店启用。新入口需要保留这一流程：未启用时提供清楚的安装引导，不能假定观影室已经可用。

Letters、Calendar 等无需全部挤进 Together；它们可以在 Home 呈现相关内容，并在 Me 保留完整入口。卡片高度按设备调整，留足滚动空间，底栏不遮挡最后一项。

## 5. Chat：和晏景说话

Chat 使用浅粉白与克制的玫粉强调色，同时延续其他页面的字体、细线和圆角。整体年轻、亲密、干净，有大面积留白，避免客服聊天或企业 IM 的观感。

- **顶部**：头像、名字、简短状态，更多操作收进菜单。
- **消息区**：双方气泡明确区分；自己用很浅的玫粉，对方用暖白或中性灰，避免厚边框和强阴影。
- **输入区**：轻盈圆润、接近悬浮式，带细边框；发送按钮使用少量玫粉，附件与语音入口保留。
- **陪伴元素**：小头像、正在输入或回复状态，可结合真实交互变化。
- **高级内容**：思考过程、工具操作、引用、附件和语音保持可展开、可操作，减少默认视觉占用。

“在线”不能用于暗示真实的人类在线状态。更合适的是实际可判断的“正在回复”“语音播放中”等；安静的陪伴文案也不能冒充实时状态。

在晏景角色配置尚未稳定前，Chat 仍需保留好友与群聊选择。以后确定默认角色后，可以让一级入口优先进入晏景，同时把切换会话放进顶部菜单，不删除现有多角色能力。

## 6. Me：我的空间与家的设置

Me 承担个人资料、全部功能索引与高级设置。建议用分组列表，减少大片装饰卡片。

| 分组 | 内容 |
|---|---|
| 我与我们 | 个人资料、角色资料入口 |
| 记录与生活 | Blog、Memory、Letters、Calendar、社交圈 |
| 外观与体验 | Day / Night、背景、字体、气泡、锁屏、动效 |
| 连接与工具 | API、MCP、外部工具、蓝牙、ICode |
| 数据与维护 | Data、备份、存储、用量、应用管理 |
| 关于 | Guide、项目说明、上游署名与许可 |

API、MCP、Data 都保留明确入口。高级功能可以收敛到二级页面，但不能因为视觉简化而难以找到。

当前已有 MCP 配置、IBMCP 客户端、初始化、工具列表与工具调用能力，并接入现有工具分发。本阶段保留，不新增连接或实现。部分音乐中转配置会回退使用 MCP 中转地址，未来调整时需注意关联。

## 7. Listen Together：把空间留给歌曲

采用 Listen Together 参考图的结构：

1. 返回 Together 与轻量双头像区域。
2. 小封面、曲名、歌手。
3. 大面积纵向歌词，当前句清楚突出。
4. 细进度条与时间。
5. 明确可操作的播放、暂停、切歌与歌单入口。

原播放器能力继续复用。参考图中控制按钮偏弱，实际设计需要补足；无歌词时显示封面与歌曲信息，不制造占位歌词。

非当前歌词保持足够对比度。当前句的字号与明暗变化应克制，避免滚动时跳动。底部控制、状态与导航之间留出安全区。

这里的“一起听”延续现有 AI 陪听能力。`CONNECTED`、`LIVE`、`ROOM`、`BRIDGE` 等词只有在存在相应真实能力时才使用，不能暗示两台设备已同步播放。

公开网易云歌单链接 / ID 的非登录导入路线属于后续独立功能，不与这次播放器外观改造绑定。

## 8. Day / Night 的关系

两种主题是同一个家的不同光线，保持布局、功能和内容一致。

| 项目 | Day | Night |
|---|---|---|
| 页面底色 | 暖白、浅粉灰 | 暖炭灰、深灰 |
| 正文 | 深灰 | 柔白 |
| 卡片 | 轻透白色 | 轻透深色 |
| 暖灯 | 淡金 | 柔和暖金 |
| 聊天强调 | 低饱和玫粉 | 稍降低亮度的玫粉 |
| 照片 | 轻遮罩 | 更深遮罩，保证文字清楚 |

尽量映射现有明暗主题机制。现有 Visual 的自定义外观应继续有效；新的默认样式不能覆盖用户已经保存的偏好。系统级配色整理可放到后续阶段，第一轮先限制在新首页与导航区域。

## 9. IB 功能的复用与原 Home 结构的取舍

可直接沿用现有 Chat、Music、Memory、Blog、Coread、Cinema、Letters、Calendar，以及 API、MCP、Data、Visual、DIY、ICode 等实现。新页面首先作为入口与呈现层；复用不代表所有在线功能已完成验证。

原 Home 可以舍弃的，是这些**一级界面形式**：

- Desk / Space / Circle 三面板作为默认首页。
- 以大量应用图标铺满首页的组织方式。
- 个人名片与 AI 名片占据首页主要空间。
- 为展示全部工具而堆积挂件的布局。

对应能力应重新安置：

- 名片进入 Me。
- 常用活动进入 Learning / Together / Chat。
- 完整应用矩阵、应用商店和桌面管理保留为“全部功能”或二级入口。
- 便笺、日程、音乐等挂件选择性进入 Home。

现有桌面排序与布局数据先保留；第一阶段不转换或删除。新共同生活空间的思路优先于原三面板形式，但不删除任何原功能。

### Memory 银河 / 生活痕迹的后续边界

银河优先作为现有 Memory 数据的另一种展示方式，不建立第二套记忆底层。未来可先只读展示，按时间、领域或重要程度组织星点，点击进入现有详情与编辑界面，不改变 ID、权限、检索、衰减或 AI 注入逻辑。

生活痕迹与 AI 长期记忆需要区分：日记、音乐与生活事件可以成为展示素材，不自动全部写入 Memory。旧银河首先借鉴表达方式，旧数据继续暂缓。

## 10. 第一阶段最适合施工的范围

建议第一阶段先完成 **统一外壳、五项导航、Home 和 Together 入口**。这能最快确认“家的感觉”，同时避开消息渲染与数据底层。

| 范围 | 第一阶段做什么 |
|---|---|
| 统一外壳 | 项目标题、基础字体与色彩、局部 Day / Night 样式 |
| 五项导航 | 接入页面入口，处理选中状态与底部安全区 |
| Home | 时间、问候、关系展示及现有生活功能入口 |
| Together | 三个活动入口，连接现有功能 |
| Learning | 可用的 Coread / 材料入口，不实现英语小屋 |
| Me | 分组入口，保证全部原功能可达 |
| Chat、Listen Together | 第一轮沿用现有功能页面，下一阶段再细化外观 |

文件范围以 `index.html` 的界面结构、局部样式和导航适配为主；名称同步涉及 `manifest.webmanifest`，项目说明涉及 README。新素材需要时放入专用 assets 目录。许可与版权说明保留，清楚标明非商业 fork 与修改者身份。

第一阶段不迁移旧数据，不导入世界书，不修改数据库、聊天管道、Memory 底层或音乐底层。角色人设导入、表情包预设和公开网易云歌单导入均属后续事项。样式使用限定作用域，避免全局替换 IB、函数名、DOM ID 或存储键。

第一阶段验收应确认：五项导航正常、所有原功能仍可访问、Day / Night 可读、底栏不遮挡内容，以及聊天、音乐、共读、观影入口没有行为回退。

**当前状态：仅保存方案。等待明确确认施工范围后再实施。**
